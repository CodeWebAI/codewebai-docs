# Comunicación y escalamiento

## Niveles de atención

- **Nivel 1:** recibe el caso, recopila información, resuelve consultas conocidas y mantiene la comunicación.
- **Nivel 2:** analiza incidencias funcionales o técnicas que requieren conocimiento especializado.
- **Nivel 3:** interviene en código, arquitectura, infraestructura, seguridad o decisiones de alto impacto.
- **Gestión de proyecto:** coordina alcance, prioridades, fechas, riesgos y comunicación ejecutiva.

Un caso puede pasar entre niveles sin perder su identificador, historial ni responsable de comunicación.

## Cuándo escalar

- Hay riesgo para la seguridad, privacidad o integridad de datos.
- El servicio está caído o el impacto aumenta.
- Se requiere acceso de producción o una modificación de infraestructura.
- El caso supera el tiempo de atención acordado.
- Existe un bloqueo entre equipos o una decisión de alcance.
- La solución puede afectar a otros clientes o proyectos.
- Se necesita aprobar costo, plazo, cambio o comunicación externa.

## Formato de escalamiento

```text
Caso:
Cliente y proyecto:
Tipo y prioridad:
Impacto actual:
Entorno afectado:
Resumen del problema:
Pasos para reproducir:
Acciones realizadas:
Evidencias y enlaces:
Hipótesis o causa conocida:
Ayuda o decisión requerida:
Próxima actualización:
```

## Comunicación de una incidencia crítica

La comunicación debe centrarse en el impacto conocido, las acciones en curso, la mitigación disponible y la próxima hora de actualización. No se deben presentar especulaciones como hechos ni compartir detalles sensibles fuera del grupo autorizado.
